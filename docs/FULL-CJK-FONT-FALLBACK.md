## Full CJK fallback for a new Simplified Chinese translation

The small official Noto `SubsetOTF/TC` fonts were sufficient for Traditional Chinese but not for the 811 additional distinct Simplified Chinese CJK codepoints introduced by `zh-Hans`. The first actual Windows Git Bash build [#44684075172](https://github.com/ymzuowei/civ2-web/actions/runs/44684075172) confirmed the missing-glyph gate fails even after regenerating from the smaller TC subset.

`tools/lang_fonts.py` now **prefers the original small pinned TC subset**. Only when its cmap lacks a needed Unicode codepoint does it fetch the official full Noto CJK TC font of the same tagged version from the upstream Noto repository, verify the exact official Git Blob SHA-1 (including Git object length/null header), and subset the full font to the combined Unicode characters actually used. The output filenames and font renderer are unchanged; no original game media or unlicensed fonts are introduced.

Pinned source Git Blob SHA values (from the official `notofonts/noto-cjk` tag tree):

- `NotoSerifCJKtc-Regular.otf`: `Serif2.003`, full TC, `a59de8d047a3ed619164a57b231e51856762ef56`.
- `NotoSansCJKtc-Regular.otf`: `Sans2.004`, full TC, `f9376bae1d421520f73a3c6c9d50b22f89548301`.

Full base fonts are downloaded only once in the runner's D: `run/lang-fonts` pinned cache, **not** bundled. Their subset output is validated by `lang_fonts.py --check` and `tests/lang_test.py` before WASM is marked PASS. If the full TC fonts also lack glyphs, the build fails rather than showing missing-character boxes. Restore the tracked source font files after copying the generated BYO static site.

No extra C: CI caches, no paid services. Recheck the Traditional and Simplified font display visually in Chrome/Edge before claiming localized gameplay acceptance.
